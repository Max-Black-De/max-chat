# store/ — состояние приложения

## Выбор стора (Р-9): Context + `useReducer`

Выбрано в F2, потому что форме входа, баннерам и основному экрану нужно общее состояние сессии.

- **Без зависимостей.** Хватает React, бандл не растёт (НФТ-6), обновлять нечего.
- **Редьюсер — чистая экспортируемая функция** (`sessionReducer` в `session.ts`). Он
  тестируется без React и DOM (`__tests__/session.test.ts`), переходы явно перечислены в union
  `SessionAction`.
- **Эффекты отдельно от состояния.** `sessionController.ts` делает запросы (через `src/api`),
  работает с хранилищами и таймерами, а наружу только диспатчит действия. Все зависимости
  инъектируются (`fetch`, `sleep`, backend'ы хранилищ, `warn`), так что контроллер тоже
  тестируется без DOM.
- **Персистентность — явная**, через `AppStorage` (`storage.ts`), а не через `persist`-middleware.
  Р-2 и Д-3 требуют версию схемы в ключе, режим «только память» при сбое записи (EC-D8/EC-D11) и
  режим «только чтение» во второй вкладке (EC-S4/EC-S10). Готовый `persist` пришлось бы так же
  оборачивать.
- **Объём состояния небольшой** (одна сессия, десятки чатов), поэтому ре-рендеры потребителей
  контекста не проблема. Контексты уже разделены: сессия (`SessionProvider`), чаты
  (`ChatsProvider`), ленты (`MessagesProvider`); пузырь — `memo`. Лимита сообщений в ленте в MVP
  нет (Р-2, v1.3.6). Если понадобится Zustand, редьюсеры и `AppStorage` переносятся без изменений.

## Модули

| Файл                    | Что                                                                                                                          |
| ----------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| `session.ts`            | `SessionState`, `sessionReducer`, селекторы (баннеры, «Нет соединения», `selectCanStartPolling`)                             |
| `sessionController.ts`  | вход / восстановление / выход, `getSettings`, учёт исходов вызовов клиента (401/403 → экран входа, 466, сеть, not-ready)     |
| `sessionCredentials.ts` | учётные данные только в sessionStorage (Р-2, НФТ-3), ключ `maxchat:session:v1`                                               |
| `storage.ts`            | `AppStorage`: `maxchat:<idInstance>:v1:<раздел>`, сбой записи → память + баннер, режим «только чтение»                       |
| `loginForm.ts`          | валидация формы входа (п. 1.2), предупреждение о чужом хосте (EC-T9)                                                         |
| `sendingRecovery.ts`    | «отправляется» → «не отправлено» после перезагрузки / выхода (ВА-20)                                                         |
| `chats.ts`              | F3: `Chat`, `chatsReducer`, сортировка (ВА-15), счётчик непрочитанных, проверка данных из localStorage (EC-D8)               |
| `chatsStorage.ts`       | F3: разделы `chats` и `phoneCache`; при загрузке — ВА-20 для всех лент                                                       |
| `messagesStorage.ts`    | F3 → F4/F5: схема ленты `messages:<chatId>` = `{ messages, index }` (§6.3), «отправляется» → «не отправлено» при чтении      |
| `messages.ts`           | F4: лента в памяти — оптимистичная отправка, ответ sendMessage, «Повторить», выход, `mergeNotificationMessage` для F5 (§6.3) |
| `sendFlow.ts`           | F4: кнопка «Отправить» (п. 3.5: пусто, > 4000, счётчик), вызов sendMessage и текст ошибки под пузырём (п. 3.4–3.6)           |
| `newChat.ts`            | F3: номер → chatId (Р-10, кеш п. 2.4, checkAccount без автоповтора, EC-I9)                                                   |
| `phoneFormat.ts`        | F3: `+7 999 123-45-67`, `+375 29 123-45-67` (Р-15, ВА-21)                                                                    |
| `texts.ts`              | тексты F2, которых нет в `src/api/messages.ts`                                                                               |

Номера телефонов и chatId — персональные данные: в логи и тексты ошибок не попадают (показывать
номер в списке чатов и шапке можно).

Токен не пишется в localStorage, в состояние после выхода, в действия (кроме `prefill` формы во
время проверки) и в логи.
